## 3. 이 저장소의 운영 원칙
단순 HTML 산출물 저장소가 아니라 **AI가 프로젝트를 이어서 작업하기 위한 Project Knowledge 저장소**로 운영합니다.

| 파일 | 역할 |
|---|---|
| `CLAUDE.md` | AI 세션의 작업 규칙과 컨텍스트 진입점 |
| `HANDOFF.md` | 새 세션에서 가장 먼저 읽는 현재 상태 요약 |
| `docs/` | 프로젝트 지식의 세부 문서 12종 |
| `index.html` | 통합 리포트 / 프로토타입 |
| `Storage/` | 구 버전 보관 |
| `push.cmd` · `push.ps1` | 커밋 · 배포 |

## 4. Source of Truth 원칙
HTML은 **표현(View)** 이며, 의사결정과 작업 상태는 문서 계층에서 관리합니다.

`docs/`에서 관리하는 것 — 프로젝트 맥락 · 현재 상태 · 의사결정 · 요구사항 · 근거 · AI/개발 제약 · 마크업 규약 · 검증 · 변경 이력 · 다음 작업 · 추적성.

C-01~C-47 요구사항의 **정의 원본은 `index.html`의 04/05 탭**이고, `docs/REQUIREMENTS.md` 3절에 **전문 사본**이 있습니다. 불일치 시 HTML이 우선입니다.

## 5. 배포

```
push.cmd                          기본 메시지로 커밋 후 push
.\push.ps1 "docs(05): 변경 내용"    메시지 지정
```

`push.ps1`은 `.git` 잠금 파일 정리 → `git add -A` → 커밋 → push 순으로 동작하고, GitHub Pages가 1~2분 내 자동 배포합니다.

> `git add -A`를 쓰므로 **작업 폴더에 임시 파일을 남기지 마세요.** 제외 대상은 `.gitignore`에 정의되어 있습니다.

## 6. 작업 완료 기준
1. 변경 대상과 영향 범위 확인
2. 파일 수정
3. 검증 실행 (`docs/VALIDATION.md` 6폭 × 3구성)
4. 결과 기록
5. `docs/PROJECT_STATE.md` 갱신
6. 필요한 경우 `docs/CHANGELOG.md` 갱신
7. `HANDOFF.md`의 다음 작업/현재 상태 갱신
8. `push.cmd`

구체적인 금지사항과 검증 조건은 `docs/RULES.md`, `docs/VALIDATION.md`를 우선 참조합니다.
