## 2. 유지해야 할 것 — 잘 작동하는 판단 3가지

개선안보다 먼저 적습니다. 아래는 계속 쓰고 **더 밀어야** 합니다.

1. **「왜 금지인지」를 함께 적는 규칙** (`RULES.md`) — "근거가 없는 규칙은 우회된다"는 전제가 정확합니다. `.fs-dim`/`.fs-veil` 혼동, foster parenting, `justify-content:center` 사고 이력이 규칙과 붙어 있어 재발이 실제로 없었습니다.
2. **실측 기반 판단** — Sticky 123→227px, 카드 노출 1.48→1.17개, 목록 뷰포트 −103px. `C-62` 이관 결정이 설득력을 가진 이유가 전부 이 숫자입니다. 취향 논쟁이 발생하지 않았습니다.
3. **도면을 프로토타입 렌더 함수로 생성** (`fsPopPaint` → `alertHtml` · `depHtml` 재사용) — **이 프로젝트에서 나온 가장 좋은 구조적 판단입니다.** 문구를 옮겨 적지 않으므로 갈라질 수 없습니다. 3절 5번에서 이걸 확장하자고 제안합니다.

## 3. 비효율 진단

### 1) 이력과 커밋이 끊겨 있다

> **2026-08-20 정정** — 최초 진단에서 「미커밋 20건 누적」으로 적었습니다. **틀렸습니다.**
> 실제 작업 트리는 깨끗하고 전부 커밋되어 있습니다. `CHANGELOG`가 전건 `Commit: —` 이고
> `PROJECT_STATE`가 「작업 N (미커밋)」으로 적어 둬서 그렇게 읽었습니다.

진짜 문제는 **연결**입니다. `CHANGELOG` 항목의 `Commit:` 칸이 전건 비어 있고, 실제 커밋 메시지는
전건 `docs: 내용 갱신` 입니다. 두 이력이 서로를 가리키지 않습니다.

비용 — 「선재 결함」(F 영역 SYS 행 중첩 · G 프레임 태그 · 부록 4 id 중복)을 발견했을 때
**어느 커밋이 원인인지 좁힐 수 없어** 매번 "기준 커밋에서 재현되는지"를 손으로 확인했습니다.
`PROJECT_STATE`의 기준 커밋 표기(`d801de9`)도 실제 HEAD 와 달랐습니다.

### 2) 검증 비용이 작업 비용을 넘어섰다

`VALIDATION.md` 2절은 17항목의 판정 기준이 **이미 코드 수준으로 명확합니다**(「`.fs-row` 안에 `.fs-row` 0건」, 「모든 배지 23×23px」, 「실측 폭 > 5px」, 「지시선 오차 2px 이내」, 「`querySelectorAll('[id]')` 중복 0」). 그런데 **사람이 브라우저에서 18조합 돌려 눈으로 확인하고 결과를 손으로 전사**합니다.

문제는 항목의 성격이 섞여 있다는 점입니다.

| 성격 | 항목 | 필요한 실행 |
|---|---|---|
| **폭과 무관** | 태그 정합 · 행 중첩 · id 중복 · 콜아웃↔명세 1:1 · 죽은 칩 · 결번 · 중복 정의 · 물량 6종 · 배지 규격 · 배지 렌더 · H 도면 9종 · 프레임 소속 10 · 변경이력 헤더 · JS 오류 | **1회 로드**로 판정 가능 |
