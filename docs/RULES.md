# RULES — AI / 개발 Guardrails

> 각 항목에는 **왜 금지인지**를 함께 적습니다. 근거가 없는 규칙은 우회되기 때문입니다.
> 마크업 구조 자체는 `docs/MARKUP.md`를 따릅니다.

## 1. 문서 성격

1. 이 산출물은 **프로토타입 · 화면설계 단계**이며 **디자인 시안 단계 이전**입니다.
2. 디자인 확정안으로 오해될 수 있는 표현을 추가하지 않습니다.
3. SCREEN 목업은 프로토타입 렌더이며 디자인 확정안이 아님을 문서 상단에 명시해 두었습니다. 이 문구를 삭제하지 않습니다.

### 명세에 쓰지 않는 것 (사용자 명시 요청으로 전량 삭제됨 — 되돌리지 말 것)
- 색상 hex (예: `#5B4BE1`)
- 폰트 크기/굵기 (예: `17.5px / 800`)
- radius · 그림자 · 그라데이션
- hover/press 시각 표현
- 요소 단위 치수 (예: `62 × 44px`, `높이 107px`)

### 반대로 반드시 유지하는 것
- **접근성 요건** — 터치 타깃 44px, 색상 단독 금지(보더 · 채움 · 라디오 **3중 단서**), WCAG 항목
- **구조 규칙** — 제공량 3열 1행, PC 2열, 혜택 유무에 따른 카드 높이 분기, 배지 최대 2개
- **표기 규칙** — 판매가 취소선 + 프로모션가
- **레이아웃 구조** — 프레임 폭 모바일 394 / PC 700px, 콘텐츠 폭 360 / 644px, 브레이크포인트 769px(C-46)

> 치수를 지울 때는 **요건이 함께 사라지지 않게** 바꿔 적습니다.
> 예) "보더 2px로 늘어날 때 padding 1px 축소(16→15)" → "선택 전후 카드 크기가 변하지 않아야 함 — 목록 흔들림 방지"

## 2. 구현상 절대 주의 — 실제로 사고가 났던 항목

1. **`.fs-frame`에 `overflow:hidden` 금지.**
   스크롤 컨테이너가 생겨 화면 sticky가 무력화됩니다. 모서리는 `>*:first-child` / `>*:last-child` 라운딩으로 처리했습니다.

2. **목업 내부의 `overflow:hidden`은 해제 상태 유지.**
   바깥으로 뺀 콜아웃이 잘립니다. `.filterbox`(펼침 애니메이션용), `.sheet-b`는 이미 해제해 두었습니다.

3. **`.fs-dim`과 `.fs-veil`을 혼동하지 않습니다.**
   `.fs-dim`은 흐린 텍스트, `.fs-veil`은 비교 시트 딤입니다. 과거 이름이 겹쳐 텍스트 span이 전면 오버레이로 변해 **페이지 전체가 어두워진 사고**가 있었습니다.

4. **`<table>`의 직접 자식으로 콜아웃을 넣지 않습니다.**
   HTML 파싱 규칙(foster parenting)으로 테이블 밖으로 밀려나 위치가 어긋납니다. 래퍼 `div`를 씁니다.

5. **가로로 넘칠 수 있는 flex 컨테이너에 `justify-content:center` 금지.**
   좌우로 동시에 넘쳐 왼쪽이 잘리고 스크롤로도 닿지 않습니다. 첫/마지막 항목에 `margin:auto`를 씁니다.

6. **sticky 오프셋 하드코딩 금지.**
   `fsSyncSticky()`가 탭바·툴바 높이를 실측해 `--tbh` / `--tlh`에 넣고, 앵커 `scroll-margin-top`이 이를 참조합니다. 구성 전환·리사이즈 시 재측정됩니다.

7. **구성 전환 시 툴바 고정 로직을 건드리지 않습니다.**
   `fsSub()`는 전환 **전에** `fsToolbarPassed()`로 위치를 판정하고, 전환 후 `fsPinToolbar()`로 툴바를 탭바 바로 아래에 되돌립니다. 짧은 구성으로 바꾸면 문서가 짧아져 스크롤이 잘리고 툴바가 떨어지기 때문입니다.
   `fsPinToolbar()`는 `html{scroll-behavior:smooth}`를 우회해 **즉시 이동**해야 합니다 (`behavior:'instant'`, 실패 시 `scrollBehavior='auto'` 폴백).

8. **리포트 문서의 1180px breakpoint를 임의 변경하지 않습니다.**
   1180px 이하에서 좌우 배치 → 세로 배치로 되돌아갑니다(명세 폭 확보 목적). 구현은 `max-width:1180px`이므로 **1180px 자체가 세로**입니다.
   > 이는 **리포트 문서 자체**의 레이아웃 기준입니다. 설계 대상 화면(S-02)의 브레이크포인트는 **769px**(C-46)로 별개입니다.

9. **전체 화면 구성 목업의 `zoom:.88`을 임의 변경하지 않습니다.**
   3~4화면을 한 행에 넣기 위한 것이며, 폭을 줄이는 방식은 탭이 두 줄로 떨어져 실제 레이아웃을 왜곡합니다.

10. **변경 이력 표는 작성일자 역순으로 마크업에 고정**입니다(JS 정렬 없음).
    행을 추가할 때 **맨 위**에 넣습니다. 검색·더보기(20건 단위)는 `fsLogPaint()`가, 헤더 건수·최근일자는 `fsLogHead()`가 처리합니다.

11. **코드 칩(`C-nn` · `O-nn`) 툴팁 로직을 임의 변경하지 않습니다.**
    `fsTipBuild()`가 정의를 수집하고 `fsTipShow()` / `fsTipGoto()`가 호버·클릭 동작을 담당합니다. 새 코드를 추가하면 정의가 자동 수집되도록 **정의는 반드시 04 또는 05 탭의 `span.cid` 행**에 둡니다.

## 3. 구조 규칙
- `rt-spec` ID를 변경하지 않습니다. 앵커·CSS가 전부 id 기준입니다.
- 탭 번호와 섹션 id가 어긋나 있습니다(`rt-spec`이 01번). `R_TABS = ['spec','proto','func','req','plan','tc']` 순서가 화면 노출 순서입니다. **id를 바꾸지 않습니다.**
- A~G PAGE CODE(`S-02_A` ~ `S-02_G`)를 변경하지 않습니다.
- 콜아웃 번호와 명세 행 번호의 1:1 관계를 유지합니다. `SYS` 행은 콜아웃 번호를 붙이지 않습니다.
- 기존 프로토타입 엔진을 임의 리팩터링하지 않습니다.
- 06 테스트 케이스 탭의 케이스 ID(`TC-*`)를 재부여하지 않습니다. 외부 수행 기록 시트의 A~I열과 대응합니다.

## 4. 변경 범위 원칙
요청 범위 밖의 파일/코드/문서 구조를 임의로 변경하지 않습니다.
변경이 필요해 보이면 먼저 영향 범위를 보고합니다.

작업 방식은 **`index.html` 직접 수정**입니다. 해당 구간은 구조 태그마다 줄바꿈이 들어가 있어 grep · 부분 치환이 가능합니다.

## 5. 커밋 위생
`push.ps1`이 `git add -A`를 쓰므로 **작업 폴더의 모든 파일이 커밋 대상**입니다.
임시 파일 · 압축 파일 · 백업본을 남기지 말고, 불가피하면 먼저 `.gitignore`에 추가합니다.
