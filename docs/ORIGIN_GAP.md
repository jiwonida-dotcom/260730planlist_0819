## 1. 최우선 — 프로세스 재배치로 깨진 의존성

### 원본 순서
```
개통방식 선택 → 유심정보입력(MO9_0201) → 가입유형 선택(MO9_0800)
  → 요금제 선택(MO9_0301) → 사은품 선택(MO9_0301_L01) → 가입자유형 선택(MO9_0400) → …
```

### TO-BE 순서 (C-24)
```
개통 방법(S-01) → 요금제 선택(S-02) → 상품 정보(S-03) → 가입 방법(S-04) → 가입자 유형(S-05) → …
```

원본에서 **가입유형(번호이동 / 신규가입 / 기기변경)은 요금제 선택보다 앞**에 있었습니다. TO-BE는 요금제 선택을 그 앞으로 옮겼으므로, 요금제 선택 시점에 **가입유형이 미확정**입니다.

### 이것이 깨뜨리는 것

| 항목 | 원본의 의존 | TO-BE에서의 문제 |
|---|---|---|
| **사은품 선택 bottomsheet** | 노출 조건 = **개통방식 + 가입유형 + 요금제** (slide 89) | 가입유형 미확정 → 사은품 목록을 확정할 수 없음. 현재 설계서에 이 화면이 **전혀 언급되지 않음** |
| **셀프개통 제약 alert** | `셀프개통 && 청소년 요금제` → 온라인신청 전환 유도 (slide 78 · 85) | 개통 방법은 S-01에서 확정되므로 판정 가능 — **영향 없음** |
| **번호이동 전용 제약** | 원칩 유심 → 신규가입 버튼 비활성 (slide 74) | 가입유형 화면 자체의 제약이므로 S-02 범위 밖 — **영향 없음** |

즉 실질 충격은 **사은품 선택 한 건**이며, 이것이 미해결이면 TO-BE 플로우가 완결되지 않습니다.

### C-48 (확정) — 사은품 선택 단계 위치 · 노출 조건
**2026-08-17 확정 · 허지원 책임 · O-21 해소**

| 항목 | 확정 내용 |
|---|---|

**TO-BE 확정 순서**
```

  → [사은품 선택 bottomsheet · 선택 대상 있을 때만] → 가입자 유형(S-05) → …
```

## 8. 기존 확정 사항과의 충돌 — 3건

여기가 문서 정합성 관점에서 가장 중요합니다.

| 확정 | 현재 문구 | 원본이 말하는 것 | 판단 |

| **C-33** | "요금제 선택 단계에 표기된 예외 조건 **없음** — 유심 유형·가입 방법 제약 요금제 부재" | 요금제 선택 시점 Alert **최소 9종** 존재 (2절) | **사실과 다릅니다.** "유심 유형·가입 방법 제약"에 한정한 서술이라면 범위를 명시해야 하고, 그대로 두면 후속 개발이 팝업을 누락합니다 |
| **C-28** | "제한 요금제는 사전 필터링 없이 **가입자 유형 선택 단계에서 예외처리** — 현행 반영되어 있어 현행 유지" | 가입자 유형 단계 처리에 **더해**, 요금제 선택 시점에도 자격 안내 Alert이 있습니다 | **불완전합니다.** 두 시점에 각각 처리가 있다는 사실을 반영해야 합니다 |
| **C-40** | "요금제 데이터의 사용 여부가 '사용'인 경우에만 노출. **백오피스와 화면의 유일한 연동 지점**이며, 그 외 노출 항목은 전부 기존 데이터·기능 활용" | CMS 연동은 최소 **7종** — 요금제 필터관리 · 요금제 그룹 · 상위/하위 요금제 · 요금제 배지 · 프로모션요금(무약정) · QoS설정 · 가격 프로모션 안내 · 제휴카드 관리 | **"유일한 연동 지점"이 성립하지 않습니다.** 의도가 "신규 개발이 필요한 연동은 사용 여부뿐"이라면 그렇게 다시 적어야 합니다 |
